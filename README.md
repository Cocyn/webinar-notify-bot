# Бот-напоминание о вебинарах — версия на GitHub Actions

Держит в Telegram одно закреплённое сообщение, в котором всегда видно:
либо занятие, которое идёт **сейчас** (дисциплина, преподаватель,
аудитория, пароль, кликабельная ссылка) + полную карточку следующего;
либо, если сейчас перерыв — карточку следующего занятия. Когда статус
меняется, бот отправляет **новое** сообщение и закрепляет его, а старое
открепляет и удаляет (так приходит уведомление); если ничего не
изменилось — молчит. Работает **без вашего компьютера и без VPS** —
GitHub бесплатно запускает скрипт каждые 5 минут в своём облаке.

## Как это устроено

- `schedule.json` — расписание (дата, время, дисциплина, преподаватель,
  аудитория). **Паролей и ссылок в нём нет** — файл спокойно можно
  хранить в публичном репозитории.
- `credentials_SECRET_paste_into_github.json` — пароли и ссылки на
  вебинары по аудиториям. **Этот файл никогда не коммитится** (он в
  `.gitignore`), а его содержимое один раз вставляется в секрет
  репозитория `CRED_JSON` (см. шаг 4) — GitHub хранит секреты в
  зашифрованном виде и не показывает их даже в логах.
- `notify_bot.py` — сам скрипт. Запускается один раз за вызов (не висит
  постоянно): смотрит текущее время, находит занятие, которое идёт
  прямо сейчас (или ближайшее следующее, если сейчас перерыв), и
  перезаписывает текст сообщения. Если текст не изменился с прошлого
  раза — Telegram просто не делает ничего (не ошибка).
- `.github/workflows/notify.yml` — правило «запускать notify_bot.py
  каждые 5 минут». Это и есть ваш бесплатный «сервер».
- **`MESSAGE_ID` / `TEXT_HASH`** — переменные репозитория (не секреты):
  id последнего отправленного сообщения и хэш его текста. По ним бот
  понимает, изменился ли статус, и какое старое сообщение удалить.
  Обновляет их отдельный шаг workflow через `gh variable set` (нужен
  секрет `ACTIONS_PAT`, см. шаг 4). Файла состояния в репозитории нет —
  бот ничего не коммитит, конфликтов из-за параллельных запусков не
  бывает.

Занятие считается «идущим» с момента начала и не дольше
`DEFAULT_DURATION_MINUTES` (по умолчанию 100 минут) — либо до начала
следующей пары в тот же день, если она раньше. Если вычисленная
длительность пары в вашем расписании обычно другая — поменяйте значение
в `.github/workflows/notify.yml`.

## Пошаговая настройка

### 1. Создайте бота в Telegram
В Telegram напишите **@BotFather** → `/newbot` → задайте имя →
получите токен вида `123456789:AA...`. Это `BOT_TOKEN`.

### 2. Узнайте CHAT_ID
- Личка с ботом: напишите ему `/start`, затем узнайте свой id через
  **@userinfobot**.
- Группа: добавьте бота в группу с правами писать/закреплять, узнайте
  id группы через **@getidsbot** (будет отрицательным, например
  `-1001234567890`).
- Канал: сделайте бота админом канала, укажите `@username_канала` или
  числовой id.

### 3. Создайте репозиторий на GitHub
1. Зарегистрируйтесь на [github.com](https://github.com), если ещё нет
   аккаунта (бесплатно, без карты).
2. Создайте **новый репозиторий** (кнопка "New repository"), тип —
   **Public** (это даёт неограниченные бесплатные минуты для Actions).
   Расписание без паролей не секретно, поэтому публичный репозиторий
   безопасен.
3. Загрузите в него все файлы из этой папки, **кроме**
   `credentials_SECRET_paste_into_github.json` (он и так в
   `.gitignore`, просто не перетаскивайте его в GitHub вручную).
   Проще всего — через веб-интерфейс GitHub: "Add file" → "Upload
   files", перетащить всё содержимое папки (кроме secret-файла).

### 4. Добавьте секреты
В репозитории: **Settings → Secrets and variables → Actions → New
repository secret**. Добавьте:

| Имя | Значение |
|---|---|
| `BOT_TOKEN` | токен из шага 1 |
| `CHAT_ID` | id из шага 2 |
| `CRED_JSON` | всё содержимое файла `credentials_SECRET_paste_into_github.json` целиком |
| `ACTIONS_PAT` | personal access token (см. ниже) — нужен, чтобы бот мог сам обновлять переменные `MESSAGE_ID`/`TEXT_HASH` |

**Как получить `ACTIONS_PAT`:** [github.com/settings/tokens](https://github.com/settings/tokens)
→ **Generate new token (classic)** → поставьте галочку **repo** →
Generate → скопируйте токен (он показывается один раз) → вставьте как
значение секрета `ACTIONS_PAT`.

После этого локальную копию `credentials_SECRET_paste_into_github.json`
можно удалить — она вам больше не понадобится, данные уже в секрете.

### 5. Запустите первый раз
Перейдите во вкладку **Actions** репозитория (GitHub может спросить
подтверждение "I understand my workflows, go ahead and enable them") →
workflow **Webinar notify bot** → **Run workflow**. Бот отправит и
закрепит первое сообщение, а переменные `MESSAGE_ID`/`TEXT_HASH`
обновятся автоматически — ничего вручную вводить не нужно.

Дальше всё работает само: GitHub будет запускать `notify_bot.py`
каждые 5 минут, 24/7, с 1 по 20 октября, и присылать новое сообщение
только когда статус реально меняется.

## Что будет 21 октября

Расписание фиксированное (последняя дата — 20.10). Как только дата
переходит за неё, бот один раз пишет «Расписание закончилось» и больше
ничего не делает при каждом запуске (но воркфлоу продолжит запускаться
каждые 5 минут — это не страшно и не тратит лишнего, т.к. при публичном
репозитории минуты Actions бесплатны без ограничений). Если хотите
полностью остановить запуски — зайдите в **Settings → Actions →
General** и отключите Actions, либо удалите/закомментируйте workflow.

Когда появится расписание на новый период — замените `schedule.json`
новыми данными (и при необходимости обновите секрет `CRED_JSON`, если
появились новые аудитории) прямо в репозитории через веб-интерфейс
GitHub — бот подхватит изменения на следующем запуске, без каких-либо
дополнительных действий.

## Проверка без Telegram (сухой прогон)

```bash
export CRED_JSON="$(cat credentials_SECRET_paste_into_github.json)"
DRY_RUN=true FAKE_NOW="2026-10-01 08:56" BOT_TOKEN=x CHAT_ID=x python3 notify_bot.py
```

`FAKE_NOW` подставляет «текущее время» — в консоли увидите, какой текст
бот бы отправил, без реальной отправки.

## Настройки (переменные окружения в workflow)

| Переменная | По умолчанию | Описание |
|---|---|---|
| `BOT_TOKEN` | — | секрет, токен бота |
| `CHAT_ID` | — | секрет, куда писать |
| `CRED_JSON` | — | секрет, пароли/ссылки по аудиториям |
| `SCHEDULE_YEAR` | `2026` | год (в schedule.json даты без года) |
| `DEFAULT_DURATION_MINUTES` | `100` | сколько минут считать пару идущей (если короче паузы до следующей) |
| `PIN_MESSAGE` | `true` | закреплять статусное сообщение |
| `TIMEZONE` | `Europe/Moscow` | часовой пояс |
